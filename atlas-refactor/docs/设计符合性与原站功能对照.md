# 设计符合性、原站功能对照与本轮改进

检查日期：2026-10-27。主站版本：v1.5.0；五个地质案例仍为 v1.4.0，本轮没有改变其算法或数据生成方式。

## 1. 结论

修改前，网站已经实现设计的主要框架，并在交互和实验展示上超过原站，但还不能说完整满足设计要求。主要问题不是缺少动画，而是部分结构化内容没有显示完整：方法结果没有按环节组织；没有案例的场景数据说明不充分；原站的部分统计、管理和案例说明仍需打开兼容工作台。

本轮已将这些缺口补入新站。按环节浏览、按方法反查、场景四段式说明、测井示范、协作者案例接入和原站主要内容管理能力均可在当前界面使用。保留了已有主题、双语、D3 全景、Three.js 地层及五个地质实验。

“满足网站的核心设计要求”不等于“每个场景都有完整实验”，也不等于真实油田生产系统。原设计明确允许暂时没有落地案例，并要求其他场景显示开发状态。

默认数据的实际规模如下；用户本地增加或隐藏内容后，界面统计随之更新。

| 项目 | 数量及解释 |
|---|---|
| 作业环节 | 13，从地质勘察到加工 |
| 场景 | 61；设计中的约 50—60 是建议范围，保留原站全部条目更有利于兼容 |
| AI 方法 | CV、TS、NLP、OPT、KG，共 5 类；本地管理支持扩展 |
| 内置完整案例 | 5 个地质案例 + 1 个测井示范，共 6 个 |
| 已覆盖场景 | 5 个；g1 同时绑定遥感岩性和构造线两个案例，不能按 6 个不同场景统计 |
| 等待完整案例的场景 | 56 个；可以阅读其业务与数据条件并直接添加案例 |
| 场景难度 | 低 5、中 42、高 14 |
| 核心字段 | 61 个场景的名称、介绍、业务问题、AI 介入点、方法、数据、难度、理由、参考方向均非空 |

数据检查记录见 [data-audit-results.json](data-audit-results.json)。这里验证的是字段存在和关联有效性，内容的专业准确性仍需要领域审核。

新增检查允许只有专业背景的旧案例。没有流程或演示会提醒；无效场景、未知方法、缺少明确指定的入口或模块语法错误会阻止添加。HTML/CSS 资源引用检查用于发现常见遗漏，无法覆盖脚本动态拼接的所有路径。

备份恢复按案例 ID 合并案例文件；备份中存在的工作区配置与隐藏名单会恢复为备份状态。恢复不是“删除当前全部案例后替换”。遇到记录不合法或场景关联错误时，不会先写入前半批有效案例。

同源迁移要求协议、主机和端口相同，不能读取其他端口或 `file://` 页面的浏览器存储。原站通过其他地址打开时，应使用可导出的备份转移内容。

## 4. 界面判断与具体优化

本轮没有继续推翻已经完成的整体视觉，也没有加入新的重复案例卡片。当前 D3 全景、地层动画、单一实验工作区已能表达项目主题；更值得改的是信息层次和操作位置。

1. **让没有演示的场景也有阅读价值。**直接显示四段方向资料，避免只有开发提示。数据清单按列区分类型、规模与标注，手机改为纵向排列。
2. **把全局比较与逐条阅读分开。**矩阵用于跨环节比较；方法页按环节分组，读者不用在长列表里反复辨认所属环节。
3. **减少已有案例页的重复正文。**完整案例上方的场景资料默认折叠为“场景速览”，需要时展开；背景、流程、演示继续承担主要教学内容。
4. **把添加入口放到需要的位置。**待补充场景、检查清单和管理概览均能添加；从场景进入时不必重新寻找分类。
5. **让管理操作可辨认。**原生管理提供明确分区、较大字号、清晰按钮、编辑反馈、自动定位编辑区域和引用保护。首次登录的用途与保存位置都有说明。
6. **保持手机可读。**新模块正文主要为 17—18 px，管理按钮和输入为 16—17 px；14—15 px 仅用于编号、ID 等辅助信息。大表格在自身区域横向滚动，不挤压整页。
7. **保持已有偏好与实验状态。**新界面支持亮暗和英文，语言与主题切换不会重算或清空现有五个实验的参数、检查位置和结果。

## 6. 仍需保留的边界与后续顺序

- **不是 61 个完整实验。**56 个场景等待专属案例，现有结构化条目可以浏览、筛选和补充，这符合设计允许逐步扩展的范围。
- **五个地质实验仍使用可复现合成数据。**它们实际执行学习、分类或聚类计算，但不应把教学指标解释为真实资料验证结果。
- **方法与数据描述需要专业审核。**特别是数据量、噪声条件、标注代价及难度是选题参考，并非通用行业标准。
- **本地管理不是服务端账号系统。**内容保存在当前浏览器，登录只控制本机编辑入口；没有多人实时协作或云端同步。常用内容应导出备份。
- **真实大规模数据和性能仍有空间。**计算默认教学规模较小，未引入 Worker、真实遥感接入、闭合 GIS 多边形或生产推理服务；Three.js 分包仍较大。
- **复杂案例资源仍建议预打包。**常见旧包和单文件协议已验证，复杂 ESM、脚本动态资源、同名文件冲突仍需专门测试。

建议先审核五个地质案例中“专业背景是否清楚、每一步是否可解释、失败情形是否可信”，再把其中一例替换为真实且可公开的数据集，最后按审核意见扩展其他环节。继续增加装饰动效的优先级低于这三项工作。

## 7. 推荐查看路径

1. 启动网站 → 作业链 → 环节与方法矩阵 → 点击一个数量验证筛选。
2. 打开计算机视觉方法页，查看按作业环节分组的场景。
3. 进入尚无案例的场景，例如 `#/scene/s1`，检查四段资料、勾选清单、参考方向及相关场景。
4. 点击“为此场景添加案例”，确认手动窗口预选所属场景。
5. 案例实验室 → 展开“接入检查与待补充场景”。
6. 页底“本地管理” → 技术 / 场景 / 案例管理；首次使用 admin / admin123，可在账号设置修改密码。
7. 备份与迁移 → 导出完整备份；协作接入 → 下载初至拾取示例 ZIP，解压后导入检查旧包展示。
