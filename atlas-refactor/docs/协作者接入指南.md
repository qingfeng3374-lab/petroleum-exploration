# 协作者接入指南

## 保持旧接口

使用原格式 `case.json` 与 `demo/` 文件夹即可，无需更改为 Svelte。原始 `firstbreak-pick-case` 就是测试样本。

顶层字段保留 `id`、`sceneId`、`title`、`version`、`updated`、`methods`；三部分仍是 `tabs.background/workflow/demo`。地质场景为 g1—g4，方法使用 cv、ts、nlp、opt、kg。具体字段参照 `case.schema.json`。

演示支持整页 HTML、旧模块导出 mount/unmount、内置 welllog-layer 引用及自动识别。HTML 包的脚本和样式会由兼容宿主内联；建议交付普通单 bundle，不依赖 ESM 分块。

一个 sceneId 可以有多个不同 id。相同 id 的案例先移除旧版本再添加。旧背景型清单可以没有流程和演示；当前101个原生学习/检索/智能优化案例要求三部分完整，并说明 What、Why、How 和各图表的检验作用。v4.0.0 共102例，覆盖全部61场景，另保留经典动态规划对照。本轮新增39例附知识来源，详见 [102案例扩充与验收](102案例扩充_知识检索与验收.md)。

## 新单文件

完整 HTML 内包含 `id="atlas-case-manifest"`、`type="application/json"` 的元信息块。结构与旧 case.json 相同，可选扩展 `extensions.atlas={version:1,views:["background","workflow","demo"]}` 表示支持宿主页签联动。

不要把完整运行脚本放进 JSON；清单中出现 script 标签会被拒绝。单文件中的实际脚本在独立的 script 元素里。新站导入时只解析元信息，不先执行上传文件。

从案例库下载现成单文件或 ZIP可以检查完整格式。`scripts/prepare.mjs` 展示如何从一个 `.case.ts` 自动生成单文件与旧包。需要双向兼容时，始终同时输出旧格式目录。

## 数据、保存和资源

每包上限 6 MiB。新站支持直接导入 ZIP：压缩前后各限 6 MiB、最多256个文件，一个 ZIP 对应一个案例；目录层级、脚本、样式和二进制资源会保留。RAR、7z 等格式请先转换或解压。核心资源本地内联，注明素材许可和数据来源。脚本在 iframe 中运行，不能假设能访问主站 DOM、localStorage 或其他案例状态。

新站包存在当前浏览器 IndexedDB，备份入口在“本地管理”；其他电脑需要重新上传或导入备份。新站可直接上传 ZIP；原站仍应先解压再上传目录。

可选联动消息为 `{atlas:true,type:"set-view",view:"background"|"workflow"|"demo"}`；案例接受前核对 `event.source===parent`，并回报 ready、resize。独立运行保留内部导航。不要以消息执行任意代码。

## 来源

业务场景数据、旧模板、初至波与测井示范来自用户提供的原项目。新案例图形、样例数据与代码在此次重构中生成，无外部图库素材。依赖的 Svelte、Vite、D3、Three.js、DOMPurify、idb、esbuild、fflate、Playwright 等保留其安装包与构建产物中的许可证声明，分发时一并遵守相应许可。
